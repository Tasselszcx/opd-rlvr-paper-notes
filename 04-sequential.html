先看例子怎么做公式解释容易混淆处结果论文区别
把训练拆成两段：前一段只让学生学固定老师，后一段撤掉老师，只按任务奖励训练。论文把它和每一步同时混合 OPD、RL 的做法作比较。

说明性例子

先找到正确做法，再提高经常做对的概率

假设学生原来完全不会一类逻辑题。学过老师以后，它已经能偶尔写出正确解法，但一次作答时仍经常选错。此时继续按结果奖励训练，就有机会把概率集中到那些已经能生成的正确解法上。

这篇先做 OPD，再做 RL，想完成的就是这两段工作。例子只是解释作者提出的分工，不表示 RL 永远只能重复已有解法。真正的证据来自下面几种训练方式的比较。

1. 第一段：学生自己答题，老师给 token 评分

学生先根据题目生成完整回答，老师再读取同样的学生前缀，给出各位置的概率。若老师比学生更认可已经生成的 token，这个位置就倾向于提高概率；若老师更不认可，就降低。这一段只使用 OPD 训练信号。

学生学习的位置来自自己的回答，因此会包含它当前容易生成的错误中间步骤。每次更新后再用新学生采样，直到选定的切换 checkpoint。老师本身保持不变，不跟着学生做 RL。

2. 第二段：加载这个学生，去掉老师信号

切换时保留第一段学到的学生参数，开始普通 GRPO。学生对同一题生成多条回答，根据结果奖励计算相对好坏，再更新学生。这一段不再叠加老师的 token 蒸馏信号，也不是另训一个新学生再合并模型。

公开脚本把这个操作写得很直接：选择 opd_then_rl 分支，提供一个已经训练好的 OPD checkpoint，然后使用 GRPO 的 advantage 计算方式。论文主比较默认在 step 60 切换，同时单独研究更早和更晚的切换时机。

两段训练换的是哪个信号

$$A_t=\begin{cases}\log\pi_T(y_t)-\log\pi_S(y_t),&\text{先做 OPD}\\A_{reward},&\text{随后做 RL}\end{cases}$$

Aₜ 表示该位置用于更新的优势信号。第一段来自师生概率差，第二段来自整条回答的奖励比较；实际实现还会处理掩码与截断。

3. 与“每一步混合两个 loss”作对照

论文比较的第一类联合方法，把奖励 advantage 和老师概率差信号直接相加。这样一次更新同时要求学生更像老师，又提高结果奖励。第二类方法则用老师信号去缩放 RL 信号，例如更强调老师支持的位置。

这些方法都可能有效，但两个目标不一定完全一致。例如老师本身对几个解法分配得比较分散，RL 想更集中地选择成功解法，而持续蒸馏又把学生拉回老师的概率。顺序方案通过在第二段移除老师，允许 RL 继续调整。

4. 分别看“一次做对”和“多试几次能做对”

Pass@1 衡量一次尝试的成功，Pass@32 或 Pass@128 衡量多次里是否至少做对一次。如果大 k 的成绩高、Pass@1 还低，说明正确回答已经有机会出现，但出现得不够稳定。只报告其中一个指标，看不到这种差别。

论文在若干任务上看到，OPD 提高了多次尝试能解决的问题范围，后续 RL 又提高了一次成功的概率。这是“先扩展，再集中”的依据。它是这些训练曲线的解释，不应该直接推广成所有 OPD 与 RL 任务都遵循的定律。

5. 再检查怎样切换，以及联合训练改了什么

作者从 step 20、60、100 的 OPD checkpoint 分别继续 RL。若第一段验证分数仍在提高，较晚切换往往更好；若早已饱和，几个切换点之后差别较小。实操应看自己的学习曲线，而不是照抄六十步。

作者还找出联合方法中与 OPD 参数变化符号不同的部分，把其中一些参数换回 OPD 的值。多次尝试成绩变好、单次成绩下降的现象，没有被随机替换同数量参数复现。这为两种训练目标之间的取舍提供了比单看最终分数更具体的证据。

02容易弄混的地方

第二段学生离老师更远，为什么还可能变好？

KL 可以因为学生概率变得更集中而增大。作者进一步分开看交叉熵和学生自己的熵，发现老师仍然给学生生成内容较高概率。不能只看到一个 KL 上升，就判断学生开始生成老师完全不认可的内容。

这是不是证明所有联合方法都不好？

不是。该比较主要使用固定外部老师。RISE 每轮从新学生构造老师，ATESD 又改变老师看到的信息；这些做法改变了比较条件。即使在本文实验里，数学上对最强几种方法也有统计持平的情况。

对需要同时使用老师和奖励的项目，它首先提供了一个简单而强的基线：把两段分开训练。做更复杂的混合损失或可学习切换时，要对齐总训练量和老师开销，再看是否真的比这条简单流程更好。

def opd_term(teacher_logprob, student_logprob, response_mask):
    """(log pi_T - log pi_S) * m -- the raw teacher signal, per token."""
    return (teacher_logprob - student_logprob) * opd_mask(response_mask)
